# FireLens dashboard

A responsive Next.js dashboard for the FireLens FastAPI service described in `API.md`. It displays raw satellite observations, corrected grid/day activity, historical analytics, and method-version validation reports, with CSV exports for all three products.

The entry point `/` is a landing page with original SVG Earth, orbital, satellite, and sensor illustrations inspired by the project's NASA Space Apps context. It uses the dashboard's navy, amber, and light/dark theme. Launch buttons open `/dashboard`; feature links open workspace views such as `/dashboard#map`, `/dashboard#activity`, and `/dashboard#validation`. The dashboard sidebar links back to the landing page. Landing illustrations and preview graphs are clearly identified as illustrative and do not fetch or invent live observations.

Use the sidebar to choose Overview, Fire Activity (calendar, trend, and seasonality), Fire Map, Detection Records (table and CSV export), Historical Analytics (comparison and anomalies), Harmonization, or Validation. Only the selected workspace is displayed, and its data queries run when that view is active. Region, date, sensor, pagination, and product filter state survive navigation. Each view has a shareable URL fragment, such as `#map` or `#validation`, and supports browser back/forward navigation. On smaller screens, the menu button opens the sidebar; Escape closes it and returns keyboard focus. Raw observation controls are hidden in the product views, which expose their own region and method filters alongside shared date controls.

## Local development

Logo exports are available in `public/firelens-logo.svg` / `.png` (flame mark) and `public/firelens-wordmark.svg` / `.png` (full logo with tagline). The backend documentation uses copies in `../backend/app/static/`. The SVG lettering is outlined for consistent rendering without installed fonts; PNG exports have transparent backgrounds. Regenerate with `pnpm export:logo`. The exporter uses the Windows Segoe UI Bold and Semibold font files; on other systems, set `FIRELENS_LOGO_BOLD_FONT` and `FIRELENS_LOGO_SEMIBOLD_FONT` to their font paths.

1. Install dependencies with `pnpm install`.
2. Copy `.env.example` to `.env.local` and set the API base URL and Swagger URL for your FastAPI deployment.
3. Start the app with `pnpm dev` and open `http://localhost:3000`.

The default service is `http://127.0.0.1:8000`. `NEXT_PUBLIC_API_BASE_URL` accepts either the service root or the versioned `/api/v1` base. Browser JSON requests go through `/api/backend/*` on the frontend origin, so they do not depend on backend CORS settings. The Next.js server must be able to reach the API; `FIRELENS_API_BASE_URL` optionally sets a separate server address for both JSON and CSV requests. `FIRELENS_API_KEY` is read only by the CSV export route; do not expose it with a `NEXT_PUBLIC_` variable.

Raw observations use `/fires`, `/fires/{id}`, `/regions`, `/calendar`, and `/analytics/*`. The table and map show satellite detections; the details dialog fetches a single detection. The region selector loads country names and codes from the lightweight `/regions/catalog` immediately, then merges `/regions` geometry details and additional countries when that slower aggregate completes. Raw requests always use three-letter country codes; integer catalog IDs are reserved for corrected activity and QA.

Corrected activity uses `/harmonization`, its calendar and analytics routes, and integer catalog region IDs from `/regions/catalog`. Apply its region, method version, and spatial grid filters independently from raw country and sensor filters. Daily heatmaps, trends, seasonal records, and historical results remain separate by method version. The UI does not sum different correction versions or invent hemisphere season names. Stored activity and uncertainty retain the backend's meaning and units; missing values remain unavailable.

Corrected views default to the imported activity method `daily-grid-modis-equivalent-v1`. Validation is requested independently with its own method, `pair-integrity-1km-30min-v1`, plus the selected catalog region and shared date range. Change either method independently, or clear its field to include all methods for that product. The grid filter is excluded from validation. Dates select reports whose validation periods overlap the range. Imported reports describe candidate-pair QA: sample size counts validated overlap pairs, and nullable MAE, RMSE, and bias are not held-out calibration metrics. Null metrics remain unavailable.

Date controls offer available years, months, and days, with the latest observed year selected by default. Availability comes from `/analytics/seasonal` over the complete API-supported date range, scoped to the selected raw country across both sensors. This returns only represented months; no study years are hardcoded. The selected year's `/calendar` supplies days with positive detection counts. Selecting a year or month includes its full inclusive period; selecting a day sets both date bounds to that day. Changing country resets the date selection to that scope's latest available year. Changing the sensor preserves the region, year, month, and day; it filters observations within that period, displaying an empty result if there are no matching detections. The harmonization workspace stays mounted while date availability reloads so its region and method filters are preserved. The resulting dates apply to raw observations, corrected activity, validation, and exports. Yearly calendars stay within 366 days, and historical comparisons stay within a single year. Insufficient history and zero variance remain API statuses; missing statistics are never shown as zero.

Metadata streaming is disabled in `next.config.mjs` to keep metadata in `<head>`. That setting alone cannot prevent extension DOM injection. `instrumentation-client.ts` runs a synchronous compatibility pass before hydration, moving only the known `clipmind-side-panel-button` element into a dedicated container whose children React does not manage. A mutation observer handles later insertion or reinsertion. Moving the original element preserves its event handlers and extension UI; dashboard nodes are left untouched. The initial dashboard render does not depend on the current date.

React Leaflet itself does not require an API key. The map defaults to OpenStreetMap standard tiles, which work without one and remain in the standard map style in both UI themes. For CARTO light/dark basemaps, request a key from [CARTO](https://carto.com/basemaps/apikey/), set `NEXT_PUBLIC_CARTO_API_KEY` in `.env.local`, and restart the dev server (rebuild for production). This key is browser-visible: restrict it to your frontend domains, including localhost for development. It is separate from the server-only `FIRELENS_API_KEY` used for exports. OpenStreetMap tiles must follow the [tile usage policy](https://operations.osmfoundation.org/policies/tiles/); use a suitable provider for higher traffic.

The map uses the dashboard's amber confidence colors and loads 1,000 detections at a time independently of the 100-row table; use **Load more detections** for subsequent map batches. Leaflet owns an SVG renderer for each map instance, avoiding reuse of a destroyed canvas context when navigating between sidebar views. Popups show the backend's acquisition time, sensor, satellite, confidence, radiative power, and coordinates. **Fit to selection** restores the region bounds or loaded detection extent. Basemaps require an internet connection.

The raw, corrected, and validation export buttons stream all matching rows from `/api/v1/exports/fires`, `/api/v1/exports/harmonization`, and `/api/v1/exports/validation` through `/api/exports/[product]`. Each export forwards only that product's supported filters, preserves the backend filename, and ignores table/map pagination. Optionally set `FIRELENS_API_BASE_URL` if the server reaches the backend at a different address. Set `FIRELENS_API_KEY` when the backend protects exports.

Run `node --test tests/api-contract.test.mjs` for API/export regression tests and `pnpm exec tsc --noEmit` for type checking. Set `FIRELENS_LIVE_TEST=1` when running the tests to additionally check the live backend and Next.js CSV route; both services must be running. `FIRELENS_PREVIEW_URL` optionally overrides `http://localhost:3000` for that check.

API response types are generated in `lib/api/schema.d.ts` from the backend's `/openapi.json`; `lib/api/types.ts` exposes aliases and UI filter types. Run `pnpm generate:api` with the local backend running to refresh them. For a different backend, run `pnpm exec openapi-typescript https://your-backend/openapi.json -o lib/api/schema.d.ts`. Regenerate after backend schema changes, then run `pnpm typecheck` and `pnpm test`.
